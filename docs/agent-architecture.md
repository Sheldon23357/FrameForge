# 创作 Agent v1

## 结构

`packages/agent/` 是不依赖 React、Electron 或密钥的核心；`context.ts` 管理上下文，`harness.ts` 管理完整运行循环，`tools/` 声明并执行编辑能力，`providers.ts` 负责四种 HTTP 服务的协议，`desktop/codex-cli.ts` 负责本机 Codex CLI 的 stdio 协议。

`desktop/agent-model.ts` 冻结单轮模型配置，在主进程发出网络请求，支持取消及一次瞬时故障重试。Gemini 默认请求原生 `streamGenerateContent?alt=sse`，180 秒没有模型内容即结束该批请求，收到有效片段则重置空闲计时；单次请求与重试合计最多 5 分钟。代理若以 404、405 或 501 拒绝流式端点，该轮回退到 `generateContent`。其他 HTTP 供应商保留 90 秒预算。`agent-settings.ts` 私下解析环境变量或系统加密密钥，不把明文密钥交给 renderer。OpenAI 使用 Responses API，DeepSeek 与 MiniMax 使用 Chat Completions。

Gemini 的正文和按需请求的官方思考摘要通过 IPC 分开推送。思考摘要在当前创作批次中显示，可以折叠，结束后不写入会话日志。内部意图规划、历史摘要、签名和工具参数不会作为增量文字推送。工具必须等到响应完整并通过现有校验才能执行；中断或截断的批次不会执行或进入模型历史。OpenAI reasoning items、Gemini thoughtSignature 和 MiniMax reasoning_content 在同一工具循环内按原协议回传，不作为助手文本展示，不写入会话日志。

Codex CLI 是第五个供应商，使用主进程子进程 `codex app-server --listen stdio://`，通过 `initialize`、`account/read`、`thread/start` 和 `turn/start` 驱动。线程是 ephemeral，模型为 `default` 时不覆盖 CLI 的默认选择。`ToolRegistry.specs()` 映射为动态工具 Schema，`item/tool/call` 由宿主校验并执行。同阶段内继续回传工具结果和修复反馈。进入新阶段或需要新工具时，以当前进度、选区和写入回执建立新线程，工具调用 ID 在所属线程内去重。历史压缩使用独立的无工具线程。单轮模型配置继续冻结。

CLI 在系统临时目录运行，以 `environments: []` 禁用原生文件和命令环境，同时关闭 shell、外部 MCP、插件、Apps、浏览器、电脑操作及记忆能力；只允许注册的动态编辑工具，不支持的客户端请求会使本轮失败。CLI 内部的原始模型状态和签名留在子进程，不转成任意 JavaScript，不写会话日志。stderr、原始 RPC 错误与 reasoning 事件不传给 renderer。取消、180 秒超时、窗口重载或应用退出均终止子进程；CLI 请求不自动重试，避免重复工具调用。连接测试为独立进程，25 秒超时且不修改工程。

程序搜索和文件选择通过 editor-only IPC 在主进程执行，使用 PATH 与有界常见目录搜索，不递归扫描整盘。用户可浏览选择程序或从多个候选中选择；npm 的 Windows shim 通过固定的 `@openai/codex/bin/codex.js` 入口启动，不拼接 shell 命令。旧版设置缺少 codex 配置时自动补入默认值，原有密钥和配置保留。这里增加的是供应商传输与应用设置，不新增编辑业务能力，因此继续复用全部已注册 Agent 工具。

`src/store/agent.ts` 协调 UI、会话保存、运行和中止；`editor-host.ts` 负责最后的原子提交。左侧 Agent 面板替换素材库，蓝图与检查器保持可用。对话切换、项目切换和隐藏面板不会让旧任务覆盖新项目。

模型设置中的豆包 TTS 用于验证火山引擎音频生成 1.0。桌面主进程从 `DOUBAO_TTS_API_KEY`（兼容 `DOUBAO_API_KEY`）或系统加密的手填密钥取值，调用固定的官方端点。测试音频在设置页试听，返回的音频和测试文本均不写入工程或设置文件。该入口属于应用设置，独立于创作 Agent 的对话模型与工程编辑工具。

## 执行核心重写

一次全剧扩写日志记录了 88 次模型请求、117 次读取和 26 次上下文整理。其中 53 次单节点正文查询与已通读的内容相同。另一次任务成功创建了节点，但节点没有接入可播放路线。两者的根因分别是把模型工具往返当作工作记忆，以及把单项写入成功当作任务完成。

执行阶段由 `engine.ts` 管理，涵盖读取、直接编辑、修复和停止。 `workspace.ts` 从当前草稿按预算构建节点、正文、时长及出边，并按节点和字段识别事实。相同节点数据可跨分页、通读、合并读取复用。模型工具往返只负责供应商协议；完整操作与结果仍可通过日志检索。对具备足够章节资料的扩写，或达到无进展读取阈值的任务，宿主暂停清单、总览和连线扫描，仍允许按已知节点 ID 单独或批量补查。重复数据只返回复用提示，混合批次继续返回缺失项。

借鉴 LangGraph 的显式阶段与状态分离，以及 AI SDK 的阶段工具选择。运行时继续使用现有的 Electron 主进程模型协议、注册工具、工程事务及检查点格式。这样可直接沿用 Codex 动态工具、Gemini 原始签名和旧工程恢复机制，无需加入框架运行时或重写供应商协议。

`edit_scene.insert` 一次创建过场并接回原自动出口。桌面即时写入时，如果本轮新建节点尚未连入路线，或者原先可达的节点因本轮操作变得不可达，则保留在草稿并反馈实际节点 ID。蓝图会显示当批的只读草稿节点和虚线连线。通过校验后转换为正式节点，停止或出错时清除预览。已有不可达节点不阻止独立修改。结构可达与条件可玩性分别检查，后者仍通过路线模拟验证。

## 上下文

- 每轮发送时拍摄工程及选中节点快照，包括所属章节、已有选项、属性、道具和素材数量；根据预算附带当前剧情工作区，优先载入选中节点与当前章节。工具只补查未提供的数据。
- 固定引用最多 20 个节点，选中项和固定项分别记录。每轮日志包含发送时的选择、工程 revision 与模型标识。已移除会话自定义提示词字段，旧文件中的该字段读取时忽略，不注入模型。
- 历史按完整 user/assistant 轮次处理，超过预算时由当前模型压缩已完成轮次为记忆摘要；原始日志保留，`read_conversation` 的 `search`、`read` 操作 可以继续检索全文和工具记录。
- 使用保守的字符估算 token。所有供应商统一使用 96,000 个估算 token 的上下文预算，并预留输出及工具空间。界面显示与运行时判断使用同一应用预算。
- 已知 ID 等相互独立的查询可通过 `read_batch` 合并 2–8 项。每页完整 JSON 响应最多 20,000 字符，空间不足时按本批剩余预算缩小，按原顺序返回完整条目。`nextOffset` 指向尚未返回的批量项；`truncatedItems` 标出独占一页仍超预算的项，可缩小读取范围或分段读取。查结局用 `read_story` 的 `list` 操作和 `kind=ending`，完整节点内容用 `read` 和 `section=notes` 分段读取。
- `edit_scene` 的 `batch` 操作一次接收 1–8 项节点操作。每项沿用单项的扁平参数，按顺序执行并返回索引、成功状态和节点 ID。单项错误不会撤回已成功的操作。先批量建节点，再用返回的真实 ID 批量连线。
- `edit_game_data` 的 `batch` 操作可混合创建、更新和删除 2–8 项属性或道具，按顺序返回每项结果和实际 ID。引用中的定义仍需先解除引用才能删除。
- `read_story.topology` 按章分页返回入口、节点 ID、自动出口和选项目标。工作区随工程草稿更新，模型可复用已载入的正文和连线。故事板、选项、节点内容与章节正文按各自的数据判断是否仍可复用。
- `read_story.playback` 从章入口或指定入口按播放器规则还原一条路线，用 `nodeIds` 定位目标，或用 `count` 取开场节点。`before` 和 `after` 控制前后范围，遇到玩家选择时按 `choiceIds` 继续，缺少选项时返回可选出口。每个节点合并正文、镜头卡对白和已绑定的声画轨道。按 `nextOffset` 续页，单节点超出预算时用返回的节点 ID 补查具体字段。
- 模型上下文在预算内附带最近三轮的部分只读结果、当前仍存在的节点引用及原日志定位。工程摘要与修订号都匹配时才复用旧查询的数值和详情；旧会话仍可复用经当前工程核实的节点引用。
- `check_story` 的 `inspect_choice` 操作从当前选中节点的选项定位后续节点事件、结构可达路线及状态引用。结果保留真实节点与规则 ID，并给出分页位置。具体条件是否满足用 `check_story` 的 `simulate` 操作验证。
- `check_story` 的 `explore` 操作从全作起点用播放器规则执行可点击的选项，返回可达结局、示例选项序列和无法到达结局的路线，并标明分页与探索是否达到上限。
- HTTP 模型接近预算时，先保存通过校验的草稿，再用原始请求、草稿信息和已执行结果索引重新建立模型上下文，自动继续同一任务。模型调用、结果和签名以完整轮次回传或移出上下文。仍可通过 `read_conversation` 的 `read` 操作（`section=tool_result`） 分页查阅本轮先前的工具结果。Codex CLI 在自己的线程内保留此前交换。
- 工程内容、备注、工具输出和历史摘要均视为参考数据。系统指令要求模型优先遵守当前用户意图；不能把剧情里的指令当作执行权限。

## 创作状态与写入范围

每轮先由所选模型结合完整请求、近期对话、检查点与当前选区输出结构化意图。这一步没有工具，宿主校验结果后才开放工具。纯进度查询直接从当前工程、最近一轮和检查点生成回执。大纲、指定章节正文与蓝图请求按结构化范围冻结为有序任务步骤。模型只生成指定步骤所需的内容和操作；宿主在工具执行前检查动作、文档或蓝图范围，按文档版本回执、指定章数以及蓝图连通性验收。作者正文保存成功后可直接结束；开放式蓝图以模型交回草稿为验收时机，由宿主判断是否可提交。会话检查点保存待办和版本回执，继续时按第一项待办恢复。对话回退点记录该轮的工程版本和可续跑任务相对工程的差异，回退时恢复两者。旧检查点仍按原有方式加载。

普通讨论直接返回正文，普通编辑直接调用注册工具。模型上下文包含工程数据的定义、用途、ID 关联和保存流程。宿主按工具 Schema 校验，检查工程结构及引用后原子提交。set_task_scope 用于恢复检查点、明确调整待办或原样复制现成正文；兼容已保存的显式范围。

作品工程的可选 `storyDesign` 保存简报、全剧大纲及按真实章节 ID 关联的文本设计。正文版本和确认状态参与工程撤销、自动保存及并发合并。游戏导出会移除作者文本。最近一份讨论稿按工程 ID 保存在本机 Agent 数据中，跨对话使用。

分章设计用 edit_chapter 的 designText 在同一次操作写入章名和正文。每章写入后更新恢复草稿，续跑时附带已有章节及正文状态，桌面编辑器在每批有效修改后写入工程，连续的 Agent 写入归为一次撤销。用户指定章数时，模型根据已有内容补齐所需章节。只有可提取完整分章正文时才走原样复制路径；表格大纲交给模型继续扩写。恢复检查点后，模型可以继续编辑或结束本轮以提交当前草稿。

## 本地 Skill

章节制作按请求分四步。`frameforge-chapter-planning` 从全局大纲写各章情节、路线和后果。`frameforge-chapter-blueprint` 写四项节点交接、选项、连线和游戏规则。`frameforge-node-screenplay` 将蓝图节点写成动作、对白、独白和声音，用 `edit_screenplay` 保存独立正文。`frameforge-node-storyboard` 读完整正文和相邻节点，产出制作分镜与玩家剧情文字。宿主按任务范围依序执行，记录节点正文版本和分镜所用正文版本。正文页从项目入口走实际选择，可以按章阅读，编辑器与 `read_screenplay` 共用路线模拟。阶段完成卡可以继续创作或打开对应产物调整，连续任务直接运行后续已指定阶段。

桌面编辑器默认将应用数据和 Chromium 会话数据保存在项目根目录的 `.local/frameforge/`，主进程启动时扫描项目根目录下的 `skills/`。使用 `FRAMEFORGE_USER_DATA` 隔离运行时，技能默认从该数据目录下的 `skills/` 加载。也可从设置选择另一目录并手动刷新目录。识别独立技能目录及仓库内的 `skills/<name>/SKILL.md`。YAML 只提供名称和用途。运行时冻结目录及受限文本资料，刷新只影响后续任务。目录列表不发送文件系统路径；工具只从快照读取，不接受任意本机路径，不运行脚本。技能文件须为普通 UTF-8 文本，扫描对目录规模、文件数量和总大小设限。

所有对话供应商共用同一目录上下文。模型按本轮交付与目录说明选出技能，宿主通过 `read_skill` 预读。执行模型可继续检索目录和参考文件，正文按字符分页。会话记录使用过的名称和内容指纹，草稿续跑拒绝已变更的技能版本。同轮上下文整理后，可从审计日志恢复阅读进度或重新读取快照。技能仅指导创作方法，工程写入继续走现有注册工具和 `commitAgentTransaction`。

Drama Skills 的分镜先读完整节点内容、所属章节剧本和实际前后节点，再核对现有镜头、角色与场景设定、素材和必要的玩家正文。Agent 创建或插入节点时必填节点内容 `notes`，供制作使用。跨互斥选项分路线输出。模型按用户指定的视频模型读取对应参考，画面提示词可以写入分镜卡，视频提示词按连续片段在对话中交付。工具没有打开媒体内容时，只报告已知素材信息或待补参考图。

静帧写作规范和示例在 `frameforge-storyboard-prompts` 的 `references/shot-card.md`。Agent 以结构对象填写 `edit_production_shot` 的 `firstFramePrompt` 或 `lastFramePrompt`，存为带段落标题的正文。两种出图入口都沿用对应帧的提示词，缺少正文时先补写。桌面生成器在正文外附加画幅、作品画风、色调和实际参考图顺序。已保存的旧版提示词仍可原样使用。

## 运行与提交

1. 创建包含 runId 的运行，冻结所选服务商与配置。
2. 准备上下文与完整工具目录，必要时压缩历史。
3. 请求模型，解析文本与工具调用，逐个校验参数并执行工具。
4. 工具写入工程副本；单个工具失败则回滚该工具，并将错误反馈给模型修复。同一运行内重复调用 ID 的写操作不重复执行；不同调用 ID 即使参数相同也作为新操作执行，允许甲→乙→甲。检查点保存 operationId 和参数指纹，旧指纹仅用于审计，不再按参数跳过新操作。
5. 模型结束时检查新增的工程错误；错误反馈给模型修复，仍不改用户工程。
6. 每批先保存可重放的检查点，再由宿主按稳定 ID 与作者的实时工程三方合并。宿主在实际候选上重验新增或受影响节点的连通性及任务回执。`commitAgentTransaction` 核对工程对象与 `changeSerial` 后写入。批次收到工程自动保存确认后才推进检查点基准。连续批次共享顶部撤销记录，中间有人工编辑时可用对话中的整轮撤销反向合并各批，保留作者改动。撤销和重做都生成更新的工程 revision。
7. 保存助手结论、工具审计记录和提交状态。停止、超时、模型错误、调用失败循环或冲突都保留日志及最近一次通过校验的草稿。

续跑先核对草稿基准的指纹。工程变化时，从草稿保存的基准或当前会话中可验证的撤销快照合并到当前工程，然后继续编辑。基准无法验证时会保留草稿并提示原因。

模型完成工具操作后，宿主检查工程结构与引用并原子提交。用户要求诊断或试玩时，可以通过 check_story 查看结果。

单章蓝图在收尾时可以保留一个待接续的可播放章尾：该节点必须从本章入口可达，且紧接的下一章已经规划但尚无节点。交付回执标出待接入的位置；如果仍有其他无去向的节点，或下一章已经搭建，校验会返回缺少出口的节点名称和 ID。

节点与查询工具的 `action` 和常用字段使用同层 JSON 对象，原有 `args` 包装仍可由注册表解析。模型 JSON Schema 和宿主 Zod 校验来自同一字段定义。事件效果数量、数值增量和节点超时接受可精确解析的数字字面量，最终保存为工程定义的数值类型。

每轮最多 100 轮模型请求和 256 次工具调用。整轮最多 20 分钟。连续三次收到相同工具错误且草稿无进展时停止。运行接近上下文预算或达到 40 组模型交换时整理上下文。审计记录保留请求次数、响应拒绝次数、最近拒绝原因和上下文整理次数。

Gemini 创作从每批最多 4 个工具调用、8,192 个输出 token 开始。批次超时、中断或被拒绝时缩为 2 个、再缩为 1 个，继续基于已通过校验的草稿、待办和回执工作。如果单次工具调用仍触到输出上限，允许在一次重试中给它更多输出空间。长篇对话可按小节自动续写，完整小节合并为一条消息；运行中断时保留已完成的小节。

## 能力与边界

提供工程、素材、节点、历史检索，节点及章节创建/修改/删除、批量移章、选项与条件、属性与道具、节点事件、画布整理、静态诊断、指定路线模拟、定位和试玩。

制作镜头卡按真实节点 ID 关联，镜头有独立稳定 ID。用 `read_story.shots` 查询并分页读取镜号，用 `edit_production_shot` 写机位、起止状态、镜长、画面提示词和尾帧提示词。点击时间线左侧的镜号可在预览区查看分镜详情。镜头卡随工程历史保存，游戏导出仅保留实际播放内容。素材引用使用已入库 ID，实际播放仍由时间线编排。

节点用所属章 ID 和实际前后节点定位剧本情节。节点内容记在 `notes`，新写或改写时需写明从哪来、已知与持有、这一段新增什么、往哪去。剧本可按章读取，也可按已知场号读取单场。edit_timeline 的 append_shot_frame 与时间线共用命令，按镜头时长添加已绑定图片。read_story.playback 的 playerTextPlayback 返回文字模式、原始与有效时长以及选择时点。

`check_story.simulate` 支持覆盖模拟初值和按毫秒等待，返回分页的节点进入顺序与状态变化。继续播放模式可在选择出现后触发定时事件；暂停模式保持原位置，选择始终由玩家做出。

选项出现时间和定时事件由检查器、时间线与 Agent 共用 `snapStoryTime`，以 0.1 秒为编辑步长，实际值仍以毫秒存储并交给同一播放器。片尾不足一档时，在有效范围内就近取整；旧工程的原值只在编辑对应时间后更新。

`edit_timeline` 的 `set_still` 为没有视频片段的节点设置 `stillAssetId` 和画面时长，独立音轨与交互仍按节点时间播放。旧图片节点首次编辑时间线时沿用原画面和有效时长。批量追加时，`add_stills` 把单图保留为第一张分镜，并将新图片按自然文件名顺序排入 `stillClips`。用 `read_story.timeline` 的 `still` 轨查询分镜 ID，再用 `update_still` 修改时长或设置入场叠化。`align_stills_to_dialogue` 按原时长比例调整图片，直到最后一段标为配音的音频结束，选项、事件和音频位置沿用原时间。

视频节点的 `timeline` 是可选增量字段，未使用它的旧工程继续按单素材和原入出点播放。`videoClips` 按顺序首尾拼接，`audioClips` 以节点开头为时间零点；每个片段具有稳定 ID。`read_story.timeline` 支持轨道、关键词与分页，并返回截断信息；`edit_timeline` 与 UI 共用 `packages/domain/timeline.ts` 的命令、时长及约束，提供视频增删、裁剪、排序、原声音量及 BGM 的偏移、长度、音量、循环和 `fadeInMs` / `fadeOutMs` 淡入淡出。淡入淡出以整段音频播放时长计算，循环时不重复包络；缺省为零，过长的淡入淡出截到实际播放长度，重叠时相乘。播放器按节点时间计算平滑音量，读档和暂停恢复后保持正确包络。`split_video` 按源素材时间分割，保留左段 ID、生成右段新 ID，不改变节点总时长与交互时间。`edit_scene` 的 `update` 操作不直接写时间线，也不覆盖时间线节点的旧素材字段。节点摘要只附带轨道数量，完整内容通过 `read_story.timeline` 读取。编辑界面保留草稿，应用时通过 `commitAgentTransaction` 校验起始工程对象与 `changeSerial`，整次剪辑形成一条历史记录；连续拖拽在草稿内同样只记一次撤销。缩略帧与真实音频波形仅在编辑端按需生成，并使用有界缓存；波形解码限制为 30 MB、10 分钟以内的音频，失败时降级。运行时使用整个时间线时长；编辑预览、桌面试玩、Windows 与网页导出共用媒体渲染组件，节点内事件、选择与存档位置均以总时间线为准。

素材检索仅返回媒体元数据。角色形象记录稳定外观，绘图补充要求单独保存。参考图以横向 3:2 保存，并使用作品画风。角色试听由默认文本模型根据角色设定选择 +20 到 +40 的语速，模型超时、不可用或结果无效时采用 +30。场景环境声保存为 20 秒循环 WAV。用户点击生成后，桌面主进程在各工程窗口之间共享队列，图像和音频可同时运行，同类任务按顺序开始。各窗口独立保存自己的工程和素材。创作 Agent 可以通过素材 ID 关联工程里已有的素材。

创作 Agent 新写或改写角色形象时至少写 200 字，声音描述至少 50 字，空白和标点不计。声音描述应将音色、节奏和语气与性格对应。场景画面应交代布局、尺度、材质、光线和固定陈设，环境声应交代主要声源及远近层次。`edit_world_setting` 校验 Agent 本次新写或改写的角色形象和声音字段。

桌面素材协议继续先按实际工程素材 ID 和安全路径定位文件，再由 `desktop/asset-response.ts` 流式响应。GET / HEAD 正确提供 Content-Length、Accept-Ranges 与 206 / Content-Range，越界或无效区间返回 416；避免直接转发 `net.fetch(file:)` 丢失区间状态导致裁剪起播卡住。该底层修复同时作用于编辑预览和独立游戏，无新增 Agent 业务命令。

播放器反馈现在使用中央逐条确认队列。队列非空时与其他游戏对话框共同阻止剧情与媒体推进；确认不改变运行时已原子执行的规则，只移除当前提示。作者仍用现有事件、效果工具配置提示来源，无须新增工具。`showMessage` 效果包含 `title`（最多 100 字）与 `text`（非空、最多 2000 字），仅显示作者编写的剧情反馈，不修改属性和道具；选项与事件工具共用 effectSchema，桌面试玩和导出播放器共用运行时消息校验及确认队列，读档不重放历史反馈。`hiddenWhenLocked` 控制已完成救人选项的隐藏，UI 与 Agent 的选项工具共用该字段。

玩家路线图只投影可展示信息：未到达节点不包含真实标题和类型，自动分支标题使用通用名称，连线不附带条件或选项规则，章节名也按探索记录隐藏。悬停和无障碍文案使用同一投影。该限制仅适用于玩家界面，编辑器与创作 Agent 继续读取完整工程以进行创作。

桌面版提供实际模型调用及本机会话文件；浏览器版可管理会话与界面布局，使用 IndexedDB 保存会话，真实调用需桌面版。会话以工程 ID 隔离，数据不放进 `.frameforge`、作品压缩包或导出游戏。

## 新能力接入

`check_story` 的 `simulate` 操作会跨过连续自动视频后再执行下一选择，并对无选择的视频循环设置 100 次上限。历史检索支持空格分隔的任意关键词匹配，按命中数及新近程度排序，返回命中词和分页截断信息；其语义在工具说明中同步提供给模型。

1. 在相应工具模块添加 `ToolDefinition`，或创建新模块并加入 `createEditorTools()`。
2. 明确工具是 read/write/view，定义最小参数 Schema、实际 ID 约束、分页和可核实结果。工具数量与用途自动进入模型目录和面板能力列表。
3. 共享业务规则、Schema 和校验器；新数据需要新增上下文投影或检索工具时一并实现。
4. 为业务规则、失败回滚、工具 JSON Schema 和宿主提交增加测试；新增外部动作必须经过受限宿主接口。
5. 更新本文与 README。扩展编辑能力不应修改模型协议适配器或 agent loop。

## 任务状态与恢复（2026-11）

旧版检查点仍可读取，续跑时沿用工程草稿和成功操作记录。对话面板提供整轮撤销。

任务具有稳定 ID。发起独立编辑时保留同一对话内挂起的任务。「继续」恢复最近一项，指定较早的任务时用它的 ID 选择检查点。回退到旧轮次时，先在对话文件登记目标工程摘要，工程确认保存后再截断对话。中断后以已打开工程的摘要判断是否完成对话回退。

作品设置、人物场景设定和游戏数据可以作为蓝图或文档任务的一部分，宿主保存每类操作的回执。打开导入对话框、生成图片、生成声音和重试外部作业分别由意图计划授权。构建或要求试玩的蓝图在连通检查后使用播放器规则模拟，锁死路线留在草稿，验收回执注明章尾接续或探索上限。

外部生成/文件选择使用 UUID 作业 ID。运行前先保存检查点中的作业记录，主进程在应用数据目录 media-jobs 保存请求指纹及结果；不会进入工程或导出。完成后取消、窗口重载或绑定前中断，续跑接回原产物；同一 ID 用于不同参数会被拒绝。导入取消也保存结果，避免自动再次弹窗。明确重新生成或再次选文件使用 newJob=true。

若主进程在远端完成但本地结果尚未落盘时崩溃，作业状态属于未知，当前供应商没有通用查询接口；系统不会盲目重复付费请求，会报告受阻，核查后由明确的新作业继续。工程撤销不删除外部生成产物。大工程仍使用整工程副本保证事务隔离，后续性能优化应根据测量实施，不以牺牲回滚安全换取速度。
