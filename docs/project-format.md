# 互动影游工程格式提案

帧叙 v0.1.1 使用工程格式 v4。这份文档描述参考实现已经支持的结构与语义，目的是让其他工具可以读取、校验和运行同一份作品。跨实现的兼容性约定仍在讨论，欢迎提交可复现的互操作问题。

## 文件与入口

- 桌面编辑器打开 UTF-8 JSON 格式的 `.frameforge`，媒体按工程目录下的相对路径引用。浏览器可交换 ZIP，根入口为 `project.frameforge`。
- HTML5 游戏使用 `game/project.json`，媒体相对 `game/files/` 解析。Windows 游戏使用 `resources/app/game/project.json`，媒体相对该文件所在目录解析。
- 载入时先通过 [parseProject 与 Schema](../packages/domain/schema.ts) 迁移和验证结构，再使用[工程校验](../packages/domain/validation.ts)检查 ID、引用和运行规则。互操作工具应分别报告这两类错误。
- `formatVersion` 表示数据格式版本。参考实现迁移旧版工程后以 v4 运行。工程的 `revision` 和 `updatedAt` 用于保存和恢复流程。

## 内容与运行语义

| 字段 | 用途 |
| --- | --- |
| `chapters`、`startNodeId` | 有序章节及各章入口。整部作品从第一章的起点进入。顶层起点随第一章同步。 |
| `scenes` | 视频节点、自动条件分支和结局。节点使用稳定 ID，`chapterId` 表示归属，选项和自动跳转引用目标节点 ID。 |
| `variables`、`items` | 声明可运行的属性和道具。属性为数值、开关或文本，道具数量为整数。隐藏属性仍参与规则判定与存档。 |
| `assets` | 视频、图片和音频的 ID、相对路径及媒体元信息。移动工程时需一并携带被引用文件。 |
| `settings`、`layout` | 工程的画幅、作者与创作设置，以及画布坐标。 |
| `storyDesign`、`screenplays`、`worldSettings`、`productionShots` | 立项、大纲、剧本、世界设定和制作镜头信息，用于制作环节。 |

### 条件、事件与时间

- 条件支持 `all`、`any`、`not`、属性比较、道具数量与访问过节点。自动分支按列出的顺序选择首个满足条件的出口。玩家选项可显示为锁定，也可按规则隐藏。
- 节点事件以 `enter`、`time`、`complete`、`exit` 标记触发时机，`once` 表示该事件每局最多执行一次。效果可设置或增减属性、增减道具、呈现需要确认的剧情提示。一批效果以事务方式应用。
- 持久化的时间单位为毫秒。节点内的选项和事件使用节点播放时间。时间线片段的媒体入出点使用对应素材的时间；轨道开始位置使用节点时间。含时间线的节点按合成时长结算片尾事件。
- 路线推进、选项、存档与恢复行为以 [剧情状态机](../packages/runtime/engine.ts) 为参考。存档记录作品内容指纹与运行状态，读取时应验证相容性。修改画布坐标不改变内容指纹。

### 创作工程与玩家发行

[导出投影](../packages/export/project.ts)从玩家版移除制作大纲、剧本、设定、镜头卡和节点备注等创作信息，保留运行所需的分支、规则和播放内容。素材引用仍会按导出功能复制。作者发布作品前应检查实际输出目录所携带的文件。

## 互操作方向

下一步需要来自不同编辑器和播放器的实现来对照同一组行为，特别是跨章节、事件顺序、选项锁定、媒体时钟和存档兼容。欢迎就这些语义提交问题或补充测试。对协议有影响的变更应以明确的版本与迁移路径描述，便于现有作品继续打开与运行。
