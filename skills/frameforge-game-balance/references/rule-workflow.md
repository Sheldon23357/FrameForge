# 规则建模、落点和复测

## 从剧情承诺选状态

「是否进过某房间」可以查访问状态。「是否看完房间里一段关键演出」需要完成事件记录，两者可能在跳转时出现差异。需要归还、消耗或显示库存的物件用道具。数值只在差异可以累计、反转或结算时使用。对同一事实选一个权威状态，避免道具和变量各记一次造成双写漂移。

把规则写成一行可审核的状态转换，记录初值、生产者、触发时间、消费者、玩家反馈及重入行为。先推各条可走路线的状态变化，再确定门槛。

## 写入顺序

1. 读既有属性、道具及相关选项的真实 ID，确认同名定义的用途。新建属性时填实际类型的初值，隐藏属性只供剧情判断。
2. 写各路线的后果节点和正常后继，再在专属节点保存 `complete` 事件。首次获得使用 once，循环结算确认每次可重复的预算与退出条件。
3. 建消费者条件。玩家选择使用可见、锁定或隐藏策略；自动节点按首个真条件命中，保留兜底。两条件相交时先列重叠状态以及期望命中项。
4. 走整条路线。结构校验核对引用和未连接节点，路线探索核对从首章起点可达的结果。涉及指定状态的路线用实际选项 ID 模拟。若探索被截断，报告已覆盖路径和缺口。

## 回归矩阵

| 风险 | 至少覆盖的输入 | 要观察的结果 |
|---|---|---|
| 线索过早生效 | 进入后果节点；正常完成；用户流程支持提前离开时再测该路径 | 后续消费者读取的值与触发点一致 |
| 判定优先级反了 | 两条件皆真；仅一项真；皆假 | 第一条有效出口和兜底均符合设计 |
| 循环可刷资源 | 第一次完成和第二次完成同一段 | 一次奖励只增加一次；循环奖励在设计上限内 |
| 消耗导致死路 | 刚好足量、差一单位、超一单位 | 不产生负库存，两侧仍有可走后继 |
| 旧工程调整初值 | 从首章新开；用户要求兼容时补旧存档场景 | 新开和存档的迁移结果按各自语义验收 |

修订记录包括具体定义、生产点、消费者、变更前后与路线证据。发现重复计分时先找重复写入和重入触发，再重算阈值。
