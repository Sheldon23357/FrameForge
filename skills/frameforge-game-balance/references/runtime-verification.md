# 规则的运行验收

## 先做状态账

每条规则记录初值与类型、读取者、写入者、触发时机、是否一次性、下限/上限、门槛失败时的出口。按路线列状态变化，包含玩家跳过的节点、短路和回环。完成同一行动的奖励和消耗应发生在其实际结算点。

| 情况 | 要跑的状态 | 证据 |
| --- | --- | --- |
| 门槛可达 | 最少资源路径、普通路径、超额路径 | 完播后的实值与可选项 |
| 阈值边界 | 阈值下一档、阈值、上一档 | 命中的真实选项或自动出口 |
| 多条件并存 | 只有 A、只有 B、A+B，必要时再测都没有 | 优先级和无条件兜底 |
| 重入 | 第一次、复访、提前跳转后再访 | 一次性效果、消耗或收益是否重复 |
| 共享目标 | 分别从每个相关入口走 | 各自的结算和后继一致 |

## 核查顺序

1. validate 检查结构和引用。不可达警告先判断是新引入、已有，还是按设计保留的作者节点。
2. explore 搜索全作实际路线。区分 finding 分页和搜索截断。结果有 `nextOffset` 继续读相关页。探索达到上限时，对高风险结局做指定模拟。
3. simulate 使用真实玩家选项 ID，沿路径检查属性、道具和结束节点。需要上游积累时从全作起点运行。若边界状态无法通过现有选择构造，保留未实测结论并注明推导依据。
4. 对新增/改动的阈值回读消费者。命中相同结局仍可能写入了错误状态，不能只数结局。

案例：拿钥匙才开机房，开门后扣 1。把扣除放在开门片段的完播事件，保留无钥匙绕行。测试钥匙为 0、1、2 的可走分支，以及复访时能否重新领钥匙。若钥匙上限或获取次数使某门槛不可达，优先修规则因果，而不是扩大无关数值。
