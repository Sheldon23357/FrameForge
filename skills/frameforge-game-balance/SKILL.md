# 帧叙数值与规则设计

1. 先确定需要判断的剧情事实和真正受规则影响的选择。用访问标记表达已经发生的节点，用布尔值表达可反转的状态，用数值表达积累，用道具表达可持有或消耗的资源。复用现有变量和道具时先查 `list_game_data` 与下游用法。
2. 为每个规则列出初值、可见性、上下限、读写点、是否可重复、玩家可感知的后果。阈值从路线能获得的状态反推。读[规则矩阵与验收](references/balance-matrix.md)处理阈值、汇流和循环。
3. 写入工程时用 `edit_game_data` 建定义，用 `edit_choice` 管门槛与跳转。选项的加减分和道具变化放在专属后果视频节点的 `edit_event`，以 `trigger=complete` 自然播完时生效。多条选项共用目标但后果不同，先走各自的后果节点再汇合。涉及消耗时检查来源、足量条件和实际生效顺序。
4. 玩家手选挂视频节点。自动判定使用条件分支，按优先级排出口，最后留无条件兜底。解释同一状态同时满足多条条件时应命中哪条。

## 验收与交接

用 `check_story.validate` 查引用和结构，用 `explore` 查可达结局和阻塞，用 `simulate` 验证明确的玩家选项序列。对边界状态检查低于、等于和高于阈值，报告预期、实测和未覆盖情况。将规则 ID、结算节点和每条可验证路线交给章节剧情规划。

需要直接测试边界时，`simulate` 可通过 initialVariables 和 initialInventory 按真实 ID 设置本次模拟初值。用 steps 指定 choose（choiceId）或 wait（durationMs）核对玩家选择和选择期间继续播放触发的节点事件。用 nextOffset 续读轨迹，比较经过节点和每步的属性、库存变化。带初值的模拟是局部边界证据；仍从工程真实起点验证玩家能否获得该状态。

规则包含共享目标、多门槛、重入，或用户要求验收结局时，读[运行验收](references/runtime-verification.md)。阶段产物包含定义、结算点、消费者与实测证据。继承已确认的剧情后果，规则矛盾反馈给章节或大纲。设计尚未落图时交付预期状态表，等对应节点存在后验证。

新增规则链或诊断同一规则的多路线差异时，读[规则建模、落点和复测](references/rule-workflow.md)。用生产点、消费者和路径状态交接。
