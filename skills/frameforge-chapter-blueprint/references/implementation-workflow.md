# 章节落图工作单

## 开工前

按章节列起点、入口边、出口边、已有节点和规则。用剧本场号和实际路线建立规划键，记录需要复用或创建的节点、上游、出边、线索和结算。有节点上限时计入选择、分支后果、自动判定、共用场戏、结局演出和总结。

## 落图顺序

1. **复用和创建**。沿用实际节点 ID。每个节点按从哪来、已知与持有、这一段新增什么、往哪去填好 `notes`，核对各条实际路线的共同事实和特有状态。无可用画面的新节点填足够理解操作和后果的占位剧情文字。
2. **接入路线**。用 `edit_chapter` 设置章起点，目标节点存在后再用真实 ID 连线。用 `edit_scene.update` 的 `patch.choiceQuestion` 可设置一行互动问题，最多 20 字。玩家选项按主技能的「玩家可见选项」直接写成自然短语，再检查字数上限。自动判定先排具体条件再加兜底。路线专属效果在独立后果节点结算。
3. **核对行为**。用 `check_story.validate` 核对所有改动，`explore` 检查可达、失败和截断，`simulate` 查指定选项序列的真实进入轨迹及数值。核对跨章继承时从全作起点开始。

| 现象 | 先查 |
| --- | --- |
| 第二章独立能开，但从第一章到不了 | 第一章的正常出口、第二章实际首节点 |
| 两路误走同一结局 | 条件的输入值、出口顺序、是否绕过后果节点 |
| 节点合并后出现悬空引用 | 入边、选项、章起点、`visited` 条件 |
| 图上有差异但玩家感受不到 | 玩家实际经过的节点内容、可见后果和事件 |

交付真实 ID 和路线验证结果，把节点的所属章、`notes` 和相邻接缝交给节点制作。
