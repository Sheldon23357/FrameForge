# 章节情节剧本

从全局大纲、用户指定章序、相关人物与场景设定、前后章交接状态起步。用 `read_story_design` 读取大纲和该章已有正文，只补读影响本章的部分。有锁定的剧情事实、结局或规则时沿用。给每场稳定的编号，使用「## 场次 1-1 场名」，改稿时沿用编号。

1. 给本章定出主角要解决的事、当前阻力和章末会发生的变化。把主线任务及可走的调查、协商、绕行等路线写成有因果的场次。
2. 逐场用情节叙述交代地点、人物、进场条件、行动、反应、发现和离场结果。对白用叙述概括其意图和传达的事实，例如「值班员否认见过来访者，却暴露自己知道证件号码」。逐句台词交给蓝图后的节点剧本正文，演出节奏交给节点制作。
   把重大结论前的证据、验证或反驳、角色反应和后果写成可以演出的拍子。技术破局至少让玩家看见决定成败的手段及结果；权力、亲疏或阵营改变要有对应的行动和代价。跨时段注明经过多久以及玩家从哪里看出状态变化。沿一条完整来路估算本章需要的演出量，再检查另一条会改变知情或结局的来路。
3. 对每个选择，写清它出现前玩家已知的依据、可执行的行动、进入的分支场次、即时看到的后果和长线影响。说明道具、参数、线索和任务状态从何处取得、何处判断，已有明确数值时写明，待定的量级保留注记。
4. 写出各分支实际发生的情节，以及返回主线、继续任务、失败或进入独立结局的出口。汇流处标明共同事实与各路线保留的知情、道具和状态，避免在共用场次提到只有一条路线知道的事。
5. 确认每个出口都指向可识别的接续场次，每个门槛有来源。用户要保存时，用 `edit_story_design` 或 `edit_chapter.designText` 写入对应章。交付作者剧本后按本轮范围结束。落实到蓝图时使用 `frameforge-chapter-blueprint`。

读[情节剧本交接格式](references/chapter-handoff.md)了解场次与出口如何写得可落图。
