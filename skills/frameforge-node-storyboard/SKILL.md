# 节点分镜与剧情文字

## 从哪里开始

锁定用户明确指定或发送时选中的视频节点。根据正文拆镜时，先用 `read_screenplay` 的 `node` 按 `nextOffset` 读完当前版本的动作、对白、独白和声音。用 `read_story.read` 的 `section=notes` 核对四项交接，按 `chapterId` 和实际前后节点补查所属章情节。旧工程单独调整已有镜头时，可利用现有镜头和节点内容。用 `read_story.playback` 或 `read_story.topology` 查实际来路和下一段，核对位置、持物、服装、对白和声画延续。汇流的共用演出只采用各入口都成立的事实。

用一句话记录整段的变化。玩家进场时怎么理解局面，离开时新增了什么事实或怀疑？把一条台词、一个动作或一个声音放在哪一镜，取决于玩家何时应该知道它。标出必须看清的线索、必须留出反应的转折、需要暂时藏住的信息，以及选项出现前玩家必须已经看到或听到的事实。

## 先排完整序列

先排戏剧节拍，再决定切成几镜。给关键台词、动作、线索和反应各标一个主要承接镜头，检查顺序、漏项与无意义重复。一个镜头可以跨剧情文字页。确有两次认知变化时，一页也可以拆成数镜。每次切换至少服务于空间、视线、行动、信息或反应中的一项。

关键对峙或揭露有两种可行拍法时，先简短比较玩家跟谁、什么时候看清线索、最后停在哪个画面。比如主观遮挡把谜底留到主角看见时，客观证据镜可以让玩家先知道，等角色察觉。挑最符合本节点叙事任务的一种。通常场景直接定案。

- **景别**随信息走。需要交代门、桌、人物的相对位置时建立空间，需要看清手怎样交接证物时才靠近。重要特写前考虑用视线或动作引导，之后决定停在证物、切回应，还是切回空间让玩家看清后果。可用主观镜头或遮挡延后揭露。相似景别相接时靠动作、视点或构图变化建立剪辑理由。
- **镜长**从动作、对白或阅读时间、反应停顿倒推。铺垫、转折和余味可以有不同速度。快切适用于确实变快的行动或连续发现，人物沉默、迟疑或逐渐理解时可以留在同一镜。重要台词落地后可以切给听者，让观众看见后果。有现成对白用实际时长，只有文本时用估算。文字叠加的场景按阅读时间对位。复核每镜起止和总长，核对关键画面与对应文字、选项出现的时点。保留已定的时点，除非本次任务授权重排。
- **篇幅不足时**，按叙事顺序补能传达过程的画面或文字页。静帧只承载实际可见的瞬间，未生成或未经核实的对白、动作和声音仍需安排可见的承载方式。沿用可用素材，但镜号和首帧复用不等于固定旧镜长。分镜制作可先改镜头卡的镜长，若已有对应图片轨且本轮允许，使用 `edit_timeline.update_still` 同步片段时长，再用 `edit_scene.update` 调整需要后移的选项时点，核对时间事件和音轨的相对位置。时点被锁定时，在交付里标出缺口及所需调整。
- **静帧的揭露时刻**就是该图切入的时刻。计划写着「本镜末尾才看清」时，如果要以静帧播放，前一张留在反应、遮挡或线索尚不清楚的画面，到揭露时点才切证物图。逐项核对出场人物、物证和结尾钩子，避免画面提前剧透。
- **切点**写清落在哪个动作或认知变化。相邻镜头对照轴线、出入画方向、视线、手与道具、服装、光向。确需转换轴线时，用可辨识的移动或重新建立空间交代。按演员站位安排前景遮挡、中景行动和后景线索。原剧本确有必要的声音才作为切入信号或跨镜连接使用。

把整段排成一张可交接的镜头表。每镜记录 **镜号｜节点内起止时间｜剧情节拍与该镜交代的信息｜景别、机位和画面重心｜行动起止、切点｜必要的台词或声响｜人物、服装、道具和参考**。跟着镜头表顺读一遍，确认铺垫和揭露顺序、反应镜的用途、动作接缝与时长。有已获认可的镜号时优先沿用。重做拆并时写明去向。

同场先记每个角色的实际穿着、脱下物件的位置，以及哪一镜才发生换装。把当前穿着写到每张看得见服装的静帧里。定妆照若是另一套服装，明确用它锁脸、发型和身份，按本场状态穿衣。需要强化一致性时，可以用已验收的同场画面补作服装参考。

## 同步编排玩家剧情文字

1. 逐个情节节拍决定由画面、对白或声音、玩家文字传达哪些信息。沿用剧本正文的对白、行动和关键揭示。需要更改戏的内容时回正文修订。承载于叠字的无声对白、独白、尚未由声画交代的事实和选择前易漏读的证据，写进 `storyboardPages`。已能清楚看见的画面细节留在镜头卡。
2. 情节描述以顺畅的短句为主。一句写一个主要动作、发现或反应。换人、换动作或出现新线索时自然断句。该保留的主语、指代和因果要写清楚，句子连起来要像自然叙述。例如「门外传来脚步声。她忙把信塞进袖口。脚步忽然停了。」
3. 按信息揭示、说话人或情绪变化分段分行，核对 `durationMs` 是否留够阅读时间。文字页和镜头各按剧情节拍切分；一页可以跨镜，一个镜头也能覆盖数页。用计划中的镜长和实际画面时点核对线索出现顺序、文字可见时长和选项出现时间。导入的成品还未核验时，把声画是否完整承载关键信息留待播放核对。
4. 写入镜头用 `edit_production_shot`，玩家剧情文字用 `edit_scene.update` 的 `patch.storyboardPages`，需要在画面上显示时设 `patch.storyboardOverlay`。使用同一个实际节点 ID，完成后读回镜头和有效播放状态。从玩家来路顺读一遍文字，确认句与句接得上，而且选择出现前相关事实已经交代。仅请求镜头或文字时，交付对应的一项。若拆镜发现台词或动作有问题，回到正文修订。若需改变剧情规则和连线，回到蓝图调整。
5. 整章制作在批量出图前，使用 `check_story.simulate` 的 `detail=pacing` 看代表性路线的净时长和逐节点的镜头计划。用 `read_story.playback` 查看关键转折前后的实际文字、静帧与可用音轨。只以玩家获得的信息复述「发生了什么、凭什么相信、为什么这样选」，并在不同来路汇流处再检查一次。数字没有异常时也要完成这项检查。入轨后复核实际时长和选项时点。

## 把镜头交给提示词

静帧和视频提示词的正文默认用中文。用户明确另行指定正文语言时，按本次要求执行。沿用节点正文中的台词。模型要求的素材标签保持原格式。

用户要求写静帧提示词时，用 `read_skill` 打开 `frameforge-storyboard-prompts`，沿用整节点镜头表，把所需帧写成一个可见瞬间。用户要求写视频提示词时，打开 `frameforge-video-prompts`，沿用同一份镜头表的动作、时长和参考，为选定的连续片段写跨帧的运动、表演、视听时序和结束状态。只要求规划时，镜头表就是交付。后续逐镜成稿发现接缝冲突时，先回镜头表修正涉及的两镜，再统一文字。

用户要求写入时用 `edit_production_shot` 按真实 ID 更新镜头卡，保存职责、机位、起止、镜长和所需提示词。玩家剧情文字独立呈现。要让已生成的首帧或尾帧播放时，用 `edit_timeline` 的 `append_shot_frame`，读回文字状态、有效时长和选项时点。用户要求生成素材时，在镜头表、参考和对应提示词就绪后使用可用的生成工具。完成一镜的本次交付就继续下一镜，读回核对整组镜号和交付内容。遇到无法使用的工具，交付已完成部分并指出哪些镜头或哪一步受阻。

新增镜头时，顶层 `action` 填 `create`，本镜动作填 `shotAction`，起止姿态填 `startState` 和 `endState`。更新已有镜头时用 `action: update`，本镜动作填 `patch.action`。用 `settingIds` 保存本镜所需的设定，只有图像生成这一回要另选参考时才覆盖。

需要可复制的模板，或节点涉及证物揭露、多角色对峙和提示词交接时，用 `read_skill` 读取[镜头表与提示词模板](references/sequence-and-prompts.md)。
