# 剧本诊断

1. 确定用户要审的稿件。用 `read_story_design` 读大纲或章节情节，用 `read_screenplay` 读对应节点正文。按实际前后节点核对四项交接。用户给了具体路线时，按真实选项 ID 读取或模拟该路线。
2. 找到能定位的因果缺口。优先核对选择前的依据、角色为什么采取当下行动、结果是否兑现、结局条件，以及不同来路汇流时玩家分别知道什么。两条路径对比时，注明共同事实和分支独有信息。
   查节奏时用 `check_story.simulate` 的 `detail=pacing` 找净播放短、计划与实播有差异或文字展示异常的节点，再用 `read_story.playback` 核对实际承载者。按一条玩家走过的路线重述关键因果，区分「有内容但读看的时间不足」与「证据、行动或反应根本没进入这条路线」。作者备注、道具数值和未制作素材用于定位缺口。
3. 每条问题写清章、场或节点，指出具体影响，并给出最小修订。区分结构错误和节奏、语气的创作建议。修订选择前的信息时，交代线索应出现在哪个动作、对白或玩家文字。
4. 诊断请求交付发现和建议。用户另外要求应用修改时，再用相应创作阶段的工具修改，并验证受影响的路线。
