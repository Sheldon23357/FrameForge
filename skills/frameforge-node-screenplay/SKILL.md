# 节点剧本正文

1. 用 `read_story.topology` 定位本章真实节点、选项和实际前后节点。用 `read_story.read` 读完整 `notes`，核对从哪来、已知与持有、这一段新增什么、往哪去四项。按 `chapterId` 查所属章剧本和必要设定。修改已有稿时用 `read_screenplay` 的 `node` 分页读取节点正文。
2. 沿该节点的演出顺序写 `action`、`dialogue`、`monologue`、`sound` 段落。动作具体可表演，逐句对白与独白加 `speaker`，需要听到的声音写出发生的时机。按场景内容使用相应段落，静默或没有独白的戏可省略相应类型。机位、镜长、提示词和玩家文字由分镜阶段安排。

   **对白以自然短句为主。** 一句推进一个意思，让人物的提问、回应、试探或打断推动节奏。一人需要交代多件事时，拆成有来有回的几拍，或把能看见的反应交给动作。保留符合身份的称谓、语气和必要因果，不为缩短而省掉关键意思。例如「三日内交差。」「三日？人手不够。」「去问林尚衣借人。」

3. 沿实际路线把对白顺念一遍，确认每句好说、好接，长段交代有清楚的停顿或反应。检查主角视角、位置、持物、关键线索和选择发生的顺序。汇流只沿用共同成立的信息。路线特有的台词与动作留在该路线的演出节点。发现线索时机、分支或结算与蓝图矛盾时，指出具体节点与影响，并在有蓝图修改请求时用蓝图步骤修订后再回验。
   旧镜长仅作参考。先写完整关键行动，例如角色发现异常、怎样验证、为何据此改变态度或选择，再估算对白、动作和停顿需要多少时间。现有结构装不下时，写清要延长或拆开的段落，把仍需演出的内容交给分镜，不在正文里用结果句带过。
4. 用 `edit_screenplay` 逐节点保存完整 `blocks`。用 `read_screenplay` 的 `route` 查看真实路线经过的正文目录，必要时用 `check_story.simulate` 核对带不同道具和状态的来路。把保存的正文交给 `frameforge-node-storyboard`。自动条件和结局总结继续使用现有节点类型与字段。
