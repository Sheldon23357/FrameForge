# 大纲成稿与修订流程

## 初稿

1. 给可用源文标章节、场次或段落位置。把原作事实、视角限制和创作者要求录入清单。关键因果保留出处，改编新生的事件注明是本轮新增。
2. 从终局往回推。分别写每个结局的玩家行动、付出、证据和兑现。把结局必需的事实逆推到玩家第一次可能看见它的地方。优先用能拍出来的对照、动作或道具变化表达信息。
3. 顺推玩家路径。对每章至少走一条路线，写「处境 → 可选行动 → 可见代价 → 下一次行动受何影响」。检验选项在点击前是否可理解，点击后是否看得到差别。
4. 给汇流做知情检查。共同段落能引用各路线交集的信息。某条路线独有事实可在下一次条件判定后回收。若后续需要两路都知道同一事实，在汇流处安排独立可见来源。
5. 交付章表、分歧矩阵、事实与兑现表。工程规模预算按各条独立后果段、共享段、自动节点和结局页估算。给章节技能说明哪些是必需节点，哪些可以并入已存在的正文。

## 返工

按「修改目标 → 受影响的事实 → 受影响的路径 → 受影响的结果」回查。改变结局条件时先找到依赖它的证据、提示和演出。已建立的工程读真实节点和条件引用。两条路径改到同一结局后，仍需保留用户承诺的差异，例如不同代价、可见反馈或不同的一段演出。

| 发现的问题 | 优先调整 | 复核证据 |
|---|---|---|
| 玩家只能猜作者心思 | 在选择前增加可见线索，或让选项说明行动方向 | 玩家点击前所见正文、选项文案 |
| 汇流后主角提到没看到的线索 | 把句子放回独立路线，或在共用段落建立信息来源 | 两条可走路线的同场台词 |
| 两个结局只改最后一行字 | 在后果演出中显现选择代价与后续人物状态 | 行动、可见结果与结局矩阵对应 |
| 改编删了揭示的原因 | 恢复原证据，或建立等价可见证据 | 来源段落和新落点 |

验收时每个承诺附实际工程证据或标明设计稿状态。大纲通过仅表示因果与覆盖已走查；运行时可达性待章节入图后用 `check_story` 核对。
