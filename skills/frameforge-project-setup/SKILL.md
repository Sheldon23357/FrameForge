# 帧叙项目设置

## 选择入口

- **从零立项**：用户只有题材、风格或一句构想时，先用一两个开放问题请用户说说想写的主角、开场处境或最想看到的场面。沿用已经明确的信息，问完等用户回应。用户要求整理简报时再提炼玩家身份、核心选择、游玩规模与制作规格。用户明确邀请提案或授权代为创作时，按其范围补充构想。
- **已有工程调整**：用 `read_project` 读取现有信息，对照用户明确提出的修改。改画幅时核对已有素材取景和后续镜头适配。
- **维护项目创作参数**：立项、制定或更新制作规格时先用 `read_project` 读取已保存的值，并参考当前项目简报和用户确定的设定。主动补齐已有明确依据的空项，通过 `update_project.creativeDefaults` 保存故事背景 `genre`、观感偏好 `tone`、受众偏好 `audience` 与具名画风 `visualStyle`。作品画幅和风格补充描述分别写入 `width` / `height` 与 `atmosphereTone`。已有值按用户的最新制作决定更新，其他值按原样沿用。依据不足的项目参数可以留空。后续创作直接读取这些项目参数。
- **只定规格**：交付简报或可选方案。用户要求应用到工程时，用 `update_project` 写入作品名、简介、作者、画幅尺寸和画风。

## 做决定

1. 根据已有素材、投放场景和游玩方式选择横屏 16:9（1920×1080）或竖屏 9:16（1080×1920）。更改画幅时同时填写宽度和高度。只修改其他设置时沿用已有工程尺寸。
2. 基础画风可用 `realistic` 真人写实或 `anime` 二次元动画。作品画风中的具名预设用 `update_project.creativeDefaults.visualStyle` 保存。角色发型、场景固定陈设等交给设定设计。
   - 从作品题材、时代地点、主要情绪与已有素材写一段可直接进入图像和视频提示词的风格补充描述。按需要补充配色、肤色、阴影、高光、材质、颗粒或线条质感。强调色由叙事或实际光源决定。保留原有光向、昼夜、剧情所需的服装颜色和线索道具辨识度。
   - 例如真人刑侦可用低饱和钢灰、石墨灰与少量冷青灰，肤色保留自然血色，暖色留给场景暖光和近处反射，高光柔和保纹理，暗部有密度且可读。不同题材从剧情重新推导配色。
   - 用户要求应用制作规格时，用 `update_project` 的 `atmosphereTone` 字段保存这段描述。已有描述优先沿用。旧工程中的 `artStyle.description` 继续用于生成。
3. 区分玩家看到的作品简介与制作简报。简介写故事承诺与玩家处境。制作简报记录镜头画幅、参考图用途、已有素材与阶段待定项，按用户要求在聊天或可写入的交付位置提供。
4. 开场由第一章起点决定。用户明确要求更换开场时，查真实章节和节点 ID，用 `edit_chapter` 更新起点，并检查章序与原有链接。

读[简报与设置映射](references/brief.md)处理已有素材的换比例、项目设置写入和简报交接。
已有画面需换比例、作品需换画风或导入旧制作规格时，读[变更影响](references/change-impact.md)。分别核实工程字段、制作决策和会失效的下游产物。

完整立项、成体系的规格变更或需要可核查的交接时，读[立项与变更工作单](references/brief-workflow.md)。按当前工程事实填写工作单。

## 阶段契约

本阶段负责作品级参数与制作简报。继承创作者已经确定的身份视角、内容尺度和制作边界。校验以实际工程读回为证据。尚无依据的生成模型参数标为待定，交给视频阶段按实际模型核对。用户只修改一个字段时仅做该项。

## 验收与交接

回读工程设置，确认已更新的故事背景、观感偏好、受众、画幅和画风。交给剧本大纲的是故事背景、受众偏好、玩家身份、故事承诺、目标规模和制作约束。交给设定与分镜的是画风、风格补充描述和最终播放画幅。
